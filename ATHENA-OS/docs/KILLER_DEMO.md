# ATHENA 5-Minute Reviewer Demonstration

The goal is one coherent technical story, not a tour of every screen.

## 0:00–0:40 — Command Center
1. Open ATHENA and complete/preview an athlete profile + daily check-in.
2. Show the six-dimensional modeled state, confidence, personal-history context, and trajectory.
3. Switch to Technical Mode to show the state is explainable rather than a magic readiness number.

**Message:** ATHENA represents a changing athlete state and exposes uncertainty.

## 0:40–1:15 — Pallas + personal history
1. Open **Pallas — Athena's close companion and friend**.
2. Ask where Relay Intelligence is; show navigation help.
3. Add a few timed results in Personal Performance Log.
4. Ask whether the latest result is faster/slower than prior personal average.

**Message:** Pallas is useful without an API key because it answers from actual locally stored ATHENA evidence; it does not invent personal history.

## 1:15–1:50 — Abstention + deterministic tools
1. Show “Why?” / counterfactuals and the non-causal warning.
2. Show safety override/abstention behavior.
3. Briefly run Relay Intelligence and point out exact evaluation of all 24 orders.

**Message:** complexity is used only where justified; deterministic problems remain deterministic and safety cannot be outvoted by a performance score.

## 1:50–3:25 — Primary NRCD research
1. Show the primary question and M0→M4/C1 model hierarchy.
2. M1: **4.023%** MAPE; M4: **3.936%** on **11,745** 2025 predictions.
3. Show Evidence Gate coverage **37.2%** and fallback outside support.
4. Show 3/3 rolling folds improved and athlete-cluster interval **[−0.098, −0.075]**.
5. Show C1 direct nonlinear model at **5.917% MAPE** and the preserved failed first model.
6. Show 2026 shift coverage dropping to **2.26%**.
7. Show rejected event-conditional interval calibration.

**Message:** ATHENA does not hide methods that lose; extra complexity must earn its place.

## 3:25–4:20 — Secondary PMData wellness validation
1. Open the wellness validation card.
2. Show W1 persistence MAE **1.029** versus W4 ATHENA **0.945**.
3. Show leave-one-participant-out: better than persistence for **12/16** people.
4. Point directly to the participant-cluster interval crossing zero.

**Message:** wellness is no longer a generic slider layer, but ATHENA still refuses to turn a small promising result into a medical or universal claim.

## 4:20–5:00 — Methods + feasibility
1. Open Methods/Feasibility.
2. Show source checksums and separate validation artifacts.
3. Show CPU-only runtime: roughly **20.3 s primary + 1.1 s secondary** in the build environment, no GPU/API/backend.
4. Show Prospective Validation Mode and explain that it cannot display a future result until real future observations satisfy the locked protocol.
5. Show the novelty boundary: ATHENA does not claim to invent dynamic athlete-state modeling.

**Closing message:** ATHENA's strength is not screen count. It is an athlete-usable system whose central mechanisms are measurable, reproducible, uncertainty-aware, and willing to fall back when evidence does not support complexity.
